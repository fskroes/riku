# Explainable Attention uses a typed lifecycle and privacy-safe evidence

**Status: accepted; implemented**

Riku must let a person understand why an Agent Session needs human input without reopening every terminal. We chose one current, structured Attention per Session: Approval required, Answer required, Review required, Session error, or the nonspecific fallback Input required. An Attention card shows its cause, how long that need has waited, and a bounded source-derived evidence preview; it does not generate an interpretation. Cards are ordered oldest-waiting-first, cannot be dismissed or acknowledged in Riku, and clear only when structured source evidence resolves the matching need. A newer structured need replaces the current one. This deliberately prefers sparse or occasionally lingering Attention over invented explanations and false reassurance.

Attention is a typed lifecycle beneath the current Session projection, not a cluster of snapshot fields. Session Sources translate tool-specific records into normalized need and resolution observations; a shared reducer owns stable Attention identities, replacement, correlated resolution, and Attention Since. Source transcripts remain authoritative and replay deterministically into the reducer, so Riku does not add a second durable event store. The retained and transported Session shape contains one atomic `attention` value or none, and board status is derived from that value plus the existing activity/staleness rule.

Evidence crosses a one-way privacy boundary on the source machine. A raw candidate exists only while its transcript record is processed and is then discarded. Local display evidence is source-faithful, sanitized, and bounded; remote evidence is a stricter rendering of allowlisted structured fields and never includes arbitrary commands, arguments, prose, or error output. Local-domain and Relay wire types are distinct so rich local state cannot become network payload accidentally. Limits and truncation are enforced before state retention and transport; the UI's three-line clamp is presentation only.

The Collector evaluates the lifecycle locally and sends only the current privacy-safe Attention projection. The Relay remains an in-memory transport/cache and does not interpret Attention. The Collector–Relay contract gains explicit protocol/capability negotiation for the richer state; legacy Attention degrades to Input required with details unavailable rather than fabricating evidence, identity, or timing. A shared conformance harness must exercise every Session Source and the Collector–Relay path for replacement, correlated resolution, replay, duplication, malformed tails, privacy, mixed-version behavior, reconnect convergence, and atomic SSE updates.

On the Board, Attention is a triage surface rather than a telemetry summary. It shows project, source tool, source machine, Attention Since, linked Work Item, and optionally branch; generic activity, model, tokens, cost, and diff do not compete with the cause and evidence. The literal action is **Open session**. Shared boards say **Needs attention**, because Attention belongs to the Session and not necessarily to the viewer; remote cards identify the machine without implying remote control. Causes share one visual priority, text carries the meaning, and notifications and transcript expansion remain separate follow-ups.

This adopts Grok Build's useful seams—typed protocol boundaries, host-independent lifecycle policy, capability-limited contributors, explicit operational limits, and reusable boundary tests—without adopting its crate granularity, agent-control scope, or a general event-storage system.

This ADR supersedes ADR 0007's decisions that browser-domain `Session` is also the Collector–Relay wire model and that the shared band is labelled “needs you.” It refines ADR 0005's attention-first stream; the stream remains, but its rows follow the explainability, ordering, privacy, and metadata rules above.
