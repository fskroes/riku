# Board UI: attention-first stream + per-project Work Items kanban

**Refined by ADR 0010:** the attention-first stream remains, but Explainable
Attention changes its row content, oldest-waiting-first order, shared-board label,
and clearing semantics. This ADR remains authoritative for choosing a stream over
status columns and for the Work Items view.

The board's primary view is an **attention-first focus board**, not status columns. The oldest Attention is the primary decision, later needs form an "Up next" queue beside it, Running Agent Sessions use compact two-tier rows below the primary decision, and Finished sessions dim below the queue. This structure was validated in the Paper Deck element prototype as variant C with variant B's Running-card treatment. Rejected: the three-column Active/Attention/Finished kanban (prototyped as variant A) because columns do not scale past a screenful and give Attention no more weight than Active; and a project-grouped grid because it buries "what needs me now" under project structure. The focus board keeps the human's one real question — "what needs me now?" — answerable at a glance while making the oldest need unmistakably primary.

Work Items get their own view, **one project at a time** (no all-projects roll-up), rendered two ways over the same item set: a **To do / In progress / Done kanban** (reusing variant A's column layout) and a **dependency graph** of those items (the C1→C2/C3→C7-style chains from the Work Map). A project selector switches projects and a source badge shows whether the items came from `WORK.md` or GitHub Issues. Each In-progress Work Item shows the Agent Session working it (the Work Link) as an inset chip, and that chip **cross-links both ways** with the session's card on the Board so a human moves between "the plan" and "the live work" without losing place. Cost accepted: two renderings of one Work Item set (kanban + graph) and bidirectional link state to keep in sync.

**Refined by #33 (Work Items dependability, from the #32 audit).** The project selector is a **native `<select>`** skinned as the Paper Deck pill, not a hand-built menu. The audit (H1) confirmed the original hand-built dropdown lacked `aria-expanded`/`aria-haspopup`, arrow-key navigation, Escape-to-close, and focus management, and named **Base UI** as the curated dependency if one was justified. Evaluating existing primitives first (the #32 constraint), the platform `<select>` closes every one of those gaps for free — keyboard traversal, type-ahead, dismissal, focus and screen-reader semantics are the browser's, with no hand-built focus behaviour — for a single-select of a short project list. Base UI was therefore **declined**: the only cost is that the open list is OS-rendered rather than carrying the `▤` menu styling, an acceptable trade for a low-frequency utility control and zero new runtime dependencies (the web app keeps only React). Base UI remains the reserved choice if a future selector needs rich per-option rendering. The four Work Items system states — loading, request failure, no project, and no Work Items — are now visually and semantically **distinct** (a structural kanban skeleton for loading; a left-aligned state panel with an icon and a single next action for the others), each in an `aria-live` region; a failed background refetch keeps the plan on screen behind a quiet "couldn't refresh" cue with Retry, rather than blanking or silently going stale (audit M1). Source identity (`WORK.md` vs GitHub Issues) stays visible in the head and in the empty state.

**Refined by #36 (Kanban into Paper Deck).** No Work Item, Work Link, source, or status semantics change; the pass is presentation + accessibility only (audit L3). Each status column is now a labelled list (`role="list"` with an accessible name carrying the status and item count, kept explicit because `list-style:none` drops list semantics in some browsers), an empty column names itself ("Nothing here yet.") rather than reading as a bare `0`, and the header progress bar carries `role="progressbar"` with value/text (the adjacent `done/total` text still conveys progress without relying on colour or the bar). Long titles, blocked-by ids, and linked project names wrap or ellipsis-truncate so a large or long-named item set never introduces page-level horizontal overflow (accessible disclosure of the truncated link name is #35's concern, not this ticket's).

**Refined by #35 (shared Agent Session elements readable & accessible, from the #32 audit).** No Session, Attention, Work Link, or routing semantics change; the pass is presentation + accessibility only (audit M2/M3/M4). Every truncated single-line fact — project, branch, activity, and the Work Link's linked project — carries a `title` so its full text is recoverable by pointer, and clamped Attention evidence is `title`-backed the same way (M2); the compact row's open-failure message is now shown as bounded, ellipsised text rather than hidden in `title` alone. Decorative glyphs (`⑂` branch, `↑` tokens, `+/−` diff, `▤ plan ↗`, `open ↗`, the tool tile letter, row status `✓/▸`, the chip `→`) are marked `aria-hidden`, and the facts they decorated get real accessible names — the token pair and diff announce as words, the branch and machine chips as labelled `role="img"` groups (the branch name announces in full even when visually clipped), the tool tile as its tool name, and a compact row's Running/Finished state as visually-hidden text so it survives outside its band. Queued Attention cards keep the **machine chip** (previously `display:none`), so a queued need exposes the same local-vs-remote context as the primary decision (M3): an Attention card carries the same facts whether it is primary or queued, differing only in density — the triage-vs-telemetry split between an Attention card and a compact Running/Finished row (ADR 0010) is deliberate and unchanged. Dense metadata wraps instead of forcing page-level horizontal overflow at narrow widths and high zoom. No new dependency (the web app keeps only React) — the single shared `:focus-visible` ring and contrast tokens folded in by #34 already make these same elements keyboard-operable and legible.

Prototype: `web/prototype/board.html` (variants A/B/C, then the converged Board + Work Items). Throwaway; fold the validated structure into `web/` during C1 (#2, the Board) and C4 (Work Items). Supersedes nothing; complements the local-first data decisions in ADR 0001–0004.
